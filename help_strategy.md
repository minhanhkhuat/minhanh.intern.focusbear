# When to Use Google, AI Tools, or Ask for Help?

1. When do you prefer using AI vs. searching Google?
- Use AI Tools: When dealing with syntax errors, explaining complex functions line-by-line, refactoring existing code snippets, or generating initial boilerplate code. AI provides instant, tailored answers without browsing multiple tabs.
- Use Google: When looking up official library documentation, troubleshooting version-specific dependencies, searching exact error tracebacks, or evaluating recent framework updates that post-date AI model training cutoffs.

2. How do you decide when to ask a colleague instead?
- Domain & Business Logic: When the bug involves internal microservice dependencies, custom business rules, or proprietary architecture that external tools cannot know.
- Sensitivity Constraints: When debugging code containing private data, customer records, or secure configurations.
- Time-Boxed Blockers: After trying to debug independently with AI and Google for 30–45 minutes without progress, escalating prevents falling into rabbit holes and losing productive time.

3. What challenges do developers face when troubleshooting alone?
- Tunnel Vision & Confirmation Bias: Sticking to a wrong hypothesis for hours while ignoring simple underlying causes.
- Time-Sinking (Rabbit Holes): Spending excessive time tweaking non-critical configurations instead of diagnosing the core issue.
- Lack of Context: Struggling with legacy codebases where architectural decisions or historical constraints are undocumented.
